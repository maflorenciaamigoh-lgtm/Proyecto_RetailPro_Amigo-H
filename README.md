RetailPro — Análisis de Ventas

Descripción del proyecto
RetailPro es una empresa distribuidora de tecnología. Este proyecto tiene como objetivo analizar la información de ventas para identificar qué categorías de productos presentan mejor desempeño y mayores oportunidades de crecimiento. El análisis busca generar información útil para apoyar la estrategia comercial y la toma de decisiones de RetailPro.

Preguntas de negocio
El análisis busca responder principalmente:
¿Qué categorías de productos generan mayores ventas para RetailPro?
¿Cómo evolucionan las ventas de cada categoría a lo largo del tiempo?
¿Qué categorías presentan mayor crecimiento y cuáles muestran una disminución en sus ventas?
¿En qué territorios se concentran las categorías de productos más vendidas?
¿Las ventas de RetailPro se concentran principalmente en clientes personas o empresas?

Herramientas utilizadas
SQL Server: utilizado para la creación de la base de datos y el análisis de la información mediante consultas SQL.
Power BI: utilizado para el modelado, análisis y visualización de los datos.
GitHub: utilizado para almacenar y organizar los archivos del proyecto.

Estructura del repositorio
El repositorio contiene archivos correspondientes a distintas etapas del proyecto:
Entrega M3.sql: crea la base de datos Ventas_Tech_DB e incorpora los datos necesarios para las consultas posteriores.
Consultas de negocio M4: contiene consultas SQL orientadas a responder preguntas de análisis sobre las ventas.
Consultas SQL M5 sobre JOIN: contiene consultas que utilizan JOIN para combinar información de distintas tablas.
Power BI — Pipeline: archivo correspondiente al trabajo realizado en Power BI sobre el Pipeline.
Power BI — Checkpoint 2: archivo correspondiente al Checkpoint 2.
README.md: documentación general del proyecto.

Orden de ejecución de los scripts en SQL Server:
Para reproducir el análisis SQL Server, se recomienda seguir el siguiente orden:
Ejecutar Entrega M3.sql para crear la base de datos Ventas_Tech_DB e incorporar los datos.
Ejecutar las consultas correspondientes a M4, que utilizan los datos cargados en la base de datos.
Ejecutar las consultas correspondientes a M5, incluyendo las consultas con JOIN.

Este orden permite asegurar que la base de datos y los datos necesarios estén disponibles antes de ejecutar las consultas de análisis.
